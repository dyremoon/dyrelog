# Code comments

Keep comments short and focused on non-obvious behavior, architectural constraints, or reasons for unusual implementation choices. Do not put changelogs, dates, prior user requests, item numbers, or accounts of already-fixed bugs in code comments.

For a comments-only cleanup, preserve executable code, literals, configuration values, legal notices, and tool directives. Verify the cleanup independently from functional changes using syntax-tree or token comparisons.
